# Sports WINNER Quant AI — 年次メンテナンス手順書 & 性能劣化防止プロトコル
**文書ID:** `MAINTENANCE-GUIDE-ANNUAL-001`  
**推奨メンテナンス周期:** **年に1回（毎年8月〜9月 / 新シーズン開幕前）**  
**対象システム:** Sports WINNER Quant AI (Web Dashboard & Python Engine)  

---

## 1. 年次メンテナンスの概要と目的

本システムは、チームの直近スタッツ（Eloレーティング、Pace、Net Rating等）を自動追従する動的特徴量エンジンを搭載しているため、**日々の再学習は不要**です。

しかし、以下の理由から**「年に1回（オフシーズン）」の定期点検とデータ追加**を強く推奨します：
1. **クラブの昇降格・再編**: B1/B2/B3の昇降格、J1/J2の昇降格による新規チームの基礎レーティング設定。
2. **リーグ平均ペースの微調整**: 審判基準や戦術トレンド（ハイペース化など）の推移をキャッチアップ。
3. **モデルの健全性検証**: 過去1年間の予測精度が想定通り維持されていたかの事後検証。

Webダッシュボード上部には、最終学習日と次回メンテナンス推奨日が表示され、期限が近づくと自動的にアナウンスが表示されます。

---

## 2. 年次メンテナンスの実行手順（3ステップ）

メンテナンスは以下の3ステップのコマンドで完了します。

### Step 1: 過去1年分の試合結果・スタッツを追加
```bash
# 前シーズンの全公式戦データを収集し、特徴量データセットを更新
python scripts/update_annual_dataset.py
```

### Step 2: モデルの年次定期再学習
過学習を防ぐため、ハイパーパラメータの過度なチューニングは行わず、固定アーキテクチャに対して新シーズン分のデータを加えてパラメータを更新します。
```bash
# Bリーグ XGBoost回帰 & サッカー Dixon-Coles の定期再学習
python scripts/retrain_models.py
```

### Step 3: 【最重要】性能劣化防止ゲート（回帰テスト）の実行
メンテ後の新モデルが、旧モデルと同等以上の予測精度を維持しているかを自動検証します。
```bash
python scripts/verify_maintenance.py
```

---

## 3. メンテ後で性能が下がらないことを確かめる合格判定基準 (Quality Gate)

新モデルを本番・GitHub Pagesに反映する前に、`scripts/verify_maintenance.py` が以下の**4大受入基準**を自動評価します。

| 評価指標 | 基準（閾値） | 旧モデル実績値 | 判定目的 |
| :--- | :---: | :---: | :--- |
| **Bリーグ 16択 Log Loss** | **$\le 2.59$** | 2.563 | 16択確率分布の劣化防止 |
| **Bリーグ 勝敗（2択）的中率** | **$\ge 70.0\%$** | 71.5% | 勝敗を見抜く基本性能の維持 |
| **サッカー 18択 Log Loss** | **$\le 2.73$** | 2.700 | サッカースコア分布の劣化防止 |
| **単体テストスイート** | **52件 全件合格** | 52/52 PASS | 既存暗号台帳・約款計算の互換性保証 |

### 自動ロールバックの原則
- 上記4基準のうち**1つでも基準を下回った場合、新モデルのデプロイは即座に中止**されます。
- `models/` 内のモデルファイルは自動的に前バージョンのバックアップへ巻き戻され（Rollback）、性能低下したモデルが本番へ流出することを物理的に遮断します。

---

## 4. Webアプリ (GitHub Pages) への反映手順

性能劣化防止ゲートに合格した新モデルをWebダッシュボードへ反映する手順：

```bash
# 1. 新モデルのパラメータと最新Eloを docs/model_data.js に出力
python scripts/export_web_model.py

# 2. GitHub へコミット & プッシュ
git add docs/ models/ data/
git commit -m "Annual Maintenance: Updated models for 2027-28 season (Quality Gate Passed)"
git push origin main
```
プッシュ後、数分で GitHub Pages が自動ビルドされ、最新モデルを搭載したWebダッシュボードが全世界に配信されます。次回メンテナンス期限も自動的に翌年（2028年9月）へと更新されます。
